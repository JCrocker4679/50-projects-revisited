# Dad Jokes — The Big Vision

## The core question
How big can we make this small idea?

It starts as 20 lines of JS that fetches a joke. The interest isn't in the code itself — it's in what happens when you treat it like a real product and use AI to execute on that vision.

## User Stories

### Core user experience
- As a user, if I don't like a joke, I don't want to see it again
- As a user, I want to filter by new jokes (ones I haven't seen before)
- As a user, I want to share jokes I like (copy, social, messaging)
- As a user, I want to save my favourite jokes
- As a user, I want to search for jokes by topic or keyword
- As a user, I want to rate jokes (so the best ones rise to the top)

### Community & moderation
- As an admin, I want a dashboard to review reported jokes
- As an admin, I want to manage user accounts
- As a user, I want to report jokes as inappropriate
- As a user, I want to suggest new jokes for review
- As an admin, I want to review and approve/reject suggested jokes

### Analytics & insights
- As an admin, I want to see which jokes are most liked
- As an admin, I want to see which jokes are most shared
- As an admin, I want analytics on joke engagement over time
- As an admin, I want reports on the "state of dad jokes" — trends, popular topics, seasonal patterns

### Growth & marketing
- Landing page — what does a proper landing page for a dad joke app even look like?
- Email — welcome emails, "joke of the day" digest, re-engagement
- User management — accounts, preferences, history
- SEO — individual joke pages, social cards, OG images
- Social presence — automated posting? Joke of the day on Twitter/X?

## Why this is interesting for the blog
This is the whole point of the series in miniature. A tutorial teaches you to fetch from an API. A product person asks "who uses this, what do they need, how does it grow?" An engineer asks "how does it scale, how do we test it, how do we deploy it?"

We're doing all three — and showing how AI handles each layer.

## Evolution path
1. **Tutorial version** → 20 lines, fetches a joke (done, this is what we have)
2. **Polished app** → Error handling, accessibility, share/copy, history, favourites
3. **Full product** → Accounts, search, ratings, personalisation ("don't show me this again")
4. **Platform** → Admin dashboard, moderation, analytics, community suggestions
5. **Business** → Landing page, email, SEO, marketing, growth

Each step is a blog post / video. Each step uses AI differently. Each step teaches something about what "production" actually means.
